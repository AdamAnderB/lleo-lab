# Contributing to LLEO
Use issues for public website errors, improvements, and non-sensitive proposals. Discuss substantial changes first. Keep participant details, unpublished results, credentials, and private concerns out of public issues.

Create a focused branch, make one coherent change, and explain the reason. For site changes run `python3 build.py` and `python3 check.py`, then inspect desktop and narrow layouts. Commit generated HTML with source edits. Review links, spelling, contrast, keyboard navigation, attribution, and the diff. Request review from @AdamAnderB before merging.

For member or research updates, confirm consent, accuracy, provenance, and project-lead approval. Respect others, welcome questions, and provide specific constructive feedback. Contact the organizer privately for conduct or privacy concerns via the contact on their personal site.

This review process is documented policy; CODEOWNERS alone does not enforce branch protection. Repository administrators can configure protected-branch review requirements separately.
