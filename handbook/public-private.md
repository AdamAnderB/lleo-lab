# Public and private boundaries
## Public website and repository
Public summaries, approved code, synthetic examples, permission-cleared stimuli, approved manuscripts/citations, tutorials, and consenting member profiles may be published here after review. Every commit, issue, pull request, and attachment may be public and copied elsewhere.

## Private project repositories
Use restricted repositories for draft plans, unpublished analyses, internal decisions, and collaboration that is not ready for release. Grant only necessary access and review it when roles change. Private GitHub is not approved storage for all types of research data.

## Approved restricted research storage
Keep participant-level exports, contact lists, consent records, identifying audio/video, linkage keys, and other sensitive data in institutionally approved storage under the applicable study protocol. Store re-identification keys separately. Do not upload these to this repository, even temporarily. De-identification is a review process, not merely removing a name column.

## Secrets
Passwords, tokens, private keys, and service credentials must never enter Git history, issues, screenshots, or public URLs. Local .gitignore rules reduce mistakes but do not enforce access control or remove prior commits.

## Release review
The project lead checks consent and approvals, disclosure risk, permissions/licenses, authorship, and the complete files/history before publication. Use synthetic fixtures for testing. Do not assume an externally linked dataset may be redistributed.

## If something is exposed
Stop further sharing. Notify the project lead privately using an established contact, identify the affected location without copying sensitive contents, and follow institutional incident procedures. Revoke exposed credentials promptly through the service owner. Deleting a file in a later commit does not erase history or downstream copies; coordinate remediation and any notifications with the responsible institution.

## Site privacy
The site has no custom login, forms, analytics scripts, or database. Hosting providers and external services apply their own policies. Following a Shiny, Gorilla, or GitHub link leaves the public site. Public member details are opt-in.
