# A project from idea to archive
## Start
Write a short proposal: question, rationale, branch connections, lead, contributors, first milestone, resources, ethics needs, and data/sharing plan. Discuss feasibility before recruitment or spending. Use the public issue template only for non-sensitive proposals; otherwise use the agreed private channel.

## Set up
Copy `templates/project/` into a new repository, choosing private by default for unreviewed research. Replace all placeholders. Agree owner and permissions, approved data storage, environment dependencies, authorship/contribution expectations, and review cadence. A repository cannot replace ethics approval or data governance.

## Work
Track bounded tasks in issues. Use branches and pull requests for code/protocol changes. Keep a dated decision log. Record experiment versions, software dependencies, seeds, and exclusions. Separate confirmatory plans from exploratory analysis. Never silently change a preregistered analysis.

## Connect to the site
After the lead approves a public summary, add its title, status, question, branch tags, consenting people, repository/materials links, and provenance to the Projects content in build.py. Label prior work, current work, completed projects, and proposed work accurately. Link people and outputs without duplicating private material.

## Release
Review every file and its history for sensitive content, rights, and reproducibility. Validate from a clean environment using synthetic or approved public data. Assign an explicit license and citation where authorized. Tag the version and link a persistent archive when one exists. Public releases require project-lead approval.

## Close
Record what was completed, limitations, contributors, final storage locations, outstanding obligations, and handover contact. Archive rather than abandon. Remove unnecessary access and update public status and member profiles with consent.
