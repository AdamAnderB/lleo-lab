# Membership, profiles, and credit
A GitHub account supports contributions; it is not a public lab membership declaration. The organizer confirms roles and project access individually.

Members may choose no listing, a name plus role, or a fuller profile. Obtain permission for the exact public text, photograph, and links. Do not publish personal contact details by default. A public profile does not grant repository access.

Edit members.json using the template guide. Set public to false to omit a member from generated pages; remove any previously generated profile HTML when withdrawing a profile and remember that past public copies may remain. Run build.py and check.py and review the People page. Only add verified links, roles, project connections, and outputs.

Distinguish current members, collaborators, and alumni. Previous coauthors are not automatically current collaborators. Preserve people’s contributions when projects finish, and agree on attribution and authorship early and revisit them as work changes.

When someone leaves, agree on handover and their public listing, update role/status, return required materials, and remove unnecessary private access. Keep appropriate contributor credit.
