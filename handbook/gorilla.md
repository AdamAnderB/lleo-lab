# Gorilla: from question to pilot
Gorilla hosts experiments; GitHub holds reviewed code, documentation, and approved materials. GitHub access does not grant Gorilla access. Ask the study lead for the correct project invitation; do not share an account.

1. Read the study question, protocol, and approved consent/recruitment plan. Check the lead’s requirements before using participant-facing materials.
2. Use a practice project to learn Task Builder 2, Questionnaire Builder 2, and Experiment Builder. The official guide is https://support.gorilla.sc/support/.
3. Define trials, stimuli, response keys, timing, randomization, counterbalancing, exclusions, and expected output columns. Keep a data dictionary alongside the protocol.
4. Assemble the experiment flow. Test consent, instructions, practice, branches, completion, and withdrawal paths.
5. Pilot with synthetic/test responses. Check supported devices, audio/headphones, screen sizes, missing responses, and exported columns. Record the Gorilla version/build identifiers and a test log.
6. Obtain the project lead’s launch approval. Confirm ethics requirements, recruitment settings, access, and any token/budget arrangements before collecting real responses. This handbook does not authorize purchases or participant recruitment.
7. Export real responses only to approved restricted storage. Document the export date and version in the private project record. Never commit raw participant exports to this public repository.
8. Publish only reviewed, permission-cleared materials. Keep a public README linking to the published Gorilla materials and record what is required to reproduce the task.

## First practice exercise
Build a two-choice task with synthetic stimuli, add instructions and a short practice block, pilot all response paths, then inspect a dummy export. Describe one design decision and one issue you found in a pull request containing only non-sensitive documentation.
